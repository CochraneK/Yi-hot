# 城市功能：后台地点审核工作台（2026-11-16）

## 解决的问题

此前 AI 候选、审核关系表与历史候选回填已落地，但操作只能经 CLI 完成。现在管理员可从后台「地点审核」进入 `/admin/geo`，查看原文链接、地名、角色、引文、文章版本和当前发布关联，并将人工判断写回同一套 `geo_candidates / geo_review_audit`。本轮不会新增模型调用，不替管理员自动确认地点。

## 实际操作

1. 登录后台，进入「内容 → 地点审核」。手机后台横向导航也有同一入口。
2. 按待审/已通过/已驳回、event/affected/publisher/mentioned、地名或文章标题筛选。默认只显示当前原文版本且仍被当前发布投影引用的分析；可勾选包含旧版本。
3. 打开原文，核对候选引文、发生地/机构地址/覆盖地的角色和地名歧义。引文存在不等于角色判断正确。
4. 选用已登记的标准地点；显示代表经纬度和可复查的来源链接。地点选项超过500条时提示使用地点搜索缩小范围，不能默默当作完整目录。
5. 填写至少4字的审核理由并勾选已经核对，才可在页面通过；也可驳回。已审记录可填写新理由重新打开，保留原有审核记录。
6. 没有对应地点时，展开「登记新的标准地点」，填写唯一 ID、名称、ISO两位代码、区域/城市、WGS84代表坐标、精度、HTTPS来源和核验理由。已有 ID 不覆盖，重复登记返回409；创建与 `audit_log` 在同一事务提交。

登记地点只是行政实体的代表坐标，不等于已确认某条新闻发生在此；批准 publisher/affected/mentioned 也不会将它们升级为 event。公开城市页仍只从 publication 层读取**通过人工审核的 event**，并保留发布、撤稿、当前分析和原文版本门槛。

## 接口、权限与审计

- `GET /api/admin/geo`：已登录的私有分页队列，每页25项；最多1000页。总数超过25000时提示缩小条件。旧版本显示警示，不允许通过；仍可驳回清理或查看历史。
- `POST /api/admin/geo/places`：登记标准地点，创建与审计原子提交，无自动外部请求。
- `POST /api/admin/geo/:id/review`：通过、驳回或重新打开。
- 全部复用 `adminHandler`：会话必需，写操作需要 CSRF，响应禁止缓存。审核人由 `actorOf(admin)` 生成，客户端不能提交 reviewer/role/status 等额外字段冒充审核者或提升候选角色。
- 原文改版、当前发布更换分析或重复批准均不能悄悄成功，返回409。审批锁住候选及对应文章行；公共读层仍独立校验来源与版本。
- 无效参数400、重复地点409；真正数据库异常不会冒充成功。

## 与此前实现的兼容

- 延续 migration 0052，不新增表，不改变既有 AI prompt、模型回执、预算、安全开关或离线回填行为。
- CLI 继续可用，`registerGeoPlace` 可选接收创建审计信息；既有调用兼容。旧候选可驳回，但过时证据不能批准；同一原文版本下已被新分析替换的旧候选也不能批准。
- 本轮没有扩展现有约60个城市的前台字典，也没有把未审候选变成地图坐标；IP估计、真实底图、全国区县目录和真实新闻样本评估仍沿 Issue #52 分别推进。
- 城市页默认地名线索与已审核视图继续分开，原有「当地」启发式标签未在本轮升级为人工核实地点；不能把审核台上线解释成全部新闻已经定位完成。

## 校验、部署与回滚

离线参数测试覆盖伪造身份/角色、分页边界、坐标类型与范围、来源和理由；PostgreSQL/API回归覆盖401/403、防缓存、地点创建审计、重复批准冲突、审批/重新打开的公开索引变化，以及旧版本拒批但可驳回。Web cache 回归新增 `/admin/geo`，验证未登录页面的私有登录跳转。

本地已通过 typecheck、Web build、43项Web回归与3项离线参数校验；合成私有API配真实构建SSR返回200，原文证据、审核操作和地点登记表单可读，响应为private/no-store。该检查不等于真实数据或生产浏览器验收。完整PostgreSQL后端测试与Docker CI通过后才合并。GitHub 合并不等于腾讯云部署：目标库须先有0052迁移，再部署 Web/API。本轮没有连接生产数据库、批量批准新闻、触发付费模型或执行真实历史回填；100条真实新闻质量抽样仍待有权限的运营者完成。

回滚移除工作台页面、导航和三个管理接口即可；保留既有地点、候选、审核审计记录与0052表。不得删掉已经形成的审批证据。
