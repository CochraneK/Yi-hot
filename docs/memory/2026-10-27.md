## SQL 时区坑（重要）
- 错误写法 `a.created_at > (now() AT TIME ZONE 'Asia/Shanghai')::date` 会把日期当 UTC 午夜比，只抓到上海 08:00 之后的切片（曾误得 18 篇）。
- 正确：`a.created_at AT TIME ZONE 'Asia/Shanghai' >= '2026-10-27'::date`（timestamptz→无时区后再比 date），或用 `to_char(a.created_at AT TIME ZONE 'Asia/Shanghai','MM-DD')` 分组。
- SSH 内 heredoc 会被 docker compose 搞坏；改用本地 heredoc 喂 stdin 给 `ssh ... "docker compose exec -T db psql"` 最稳。

## CI 红：`tests/offpeak-history.test.ts` 只在非高峰时段能过（已修，9aff4cb）
- 现象：`peak sweep ... leaves history for the half-price window` 断言 line 64 失败；
  同一 commit 有时绿有时红 → 不是 flaky，是**依赖 CI 真实运行时刻**。
- 根因：`sweepUnprocessed(now)` 传了时间，但内部 `queueProcessing(id)` 没接，
  line「`if (r.historical && holdsHistoryForOffPeak())`」与 `peakSlotsLeft()` 都读 `Date.now()`。
  CI 在北京 14–18 点跑 → 第二次 sweep 明明传了 OFF_PEAK，仍按高峰把历史稿退回 → 断言 false。
- 修法：`queueProcessing(id, { now })` 加可选 now 透传（不传 = Date.now()，生产行为不变），
  sweep 里 `queueProcessing(r.id, { now })`。**验收要在北京高峰时段跑**才算数。
- 在服务器上跑单个后端测试的办法（宿主无 npm）：
  `sudo docker exec -e DATABASE_URL='postgres://aihot:<pw>@db:5432/aihot_ci' aihot-api-1 node --test tests/xxx.test.ts`
  （`aihot_ci` 已 migrate，64 张表；库名必须以 `_test`/`_ci` 结尾否则 tests/setup.ts 拒绝跑）。
