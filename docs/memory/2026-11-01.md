# 2026-11-01

## 修「三个站的标签页都挂 Yi-Hot 徽章」（12:15–12:40 CST）

用户报的不只是 yihot：**根路径门户、`/futureme/`、`/anydoor/` 的浏览器标签页全是
save the children 的图**。

根因（两半，缺一不可）：
1. `root.tsx` 的五条 `<link>` 写的是**根路径**（`/logo.svg`、`/favicon.ico`…）。原生
   `<link href>` 不吃 React Router 的 basename，所以浏览器请求的是站点根——而根路径
   是「项目入口」门户的地盘，只是靠 Caddy 兜底才落到 yihot 的 api。
2. 门户页、futureme、anydoor **都没有 `<link rel="icon">`**，浏览器于是自动回退到根
   `/favicon.ico`，拿到 yihot 的品牌图。三方 md5 完全相同（6390 字节 `30ffda1b…`）。

修法（**只在 server.ts 一处实现**，80 与 443 共用）：
- `root.tsx` + `static.ts`：图标 / manifest icons / RSS 全部补 `/yihot/` 前缀。
- `server.ts`：根 `/favicon.ico`、`/apple-touch-icon*.png` → **204**；新增
  `/portal-icon.svg`（深绿拱门，内联常量）。
- `portal.html`：声明自己那个 SVG。Caddy **刻意不接管**这些路径，靠兜底反代。
- `smoke.ts`：favicon 断言改到 `/yihot/favicon.ico`。

**踩过的坑**：第一版把 204 和内联 SVG 写在 Caddy 里，后来发现 80 端口根本不过 Caddy
（`/futureme/` 在 80 上由 `server.ts` 反代），于是 http 访问 futureme 仍拿 yihot 图标。
两处各写一遍正是这次串站的成因，所以改成单一实现、Caddy 只留兜底。

顺带核实的事实：
- **HTTPS 早就有了**：Let's Encrypt 给 IP 签的 short-lived 证书（约 6 天，SAN=`IP Address`），
  10-29 签发、Caddy 自动续期。`docs/DOMAIN_AND_HOSTING.md` 里「HTTPS 未启用」「无 HTTPS」
  是 10-20 的旧状态，已更正。
- **Caddy 容器 rootfs 只读**（`docker cp` 进不去），校验只能
  `docker run --rm --entrypoint caddy -v /tmp/新文件:/etc/caddy/Caddyfile:ro caddy:2.11.7-alpine validate`；
  `admin off` 让 reload 不可用，改配置必须 `docker restart futureme-https`（443 断几秒）。
- **线上 `portal.html` 比本地新**（多了 AnyDoor 卡片与描述），是之前在服务器上直接改的。
  已把线上版回写本地再叠加改动——**以后改这台机器上的文件先拉线上版对比**。

提交（已推送，远端 main = `4ce8ca9`）：
`f53ebca` fix(icons) / `895e3cb` feat(nav) / `4ce8ca9` docs(财务+HTTPS 更正)。

## 周报主题数：上限换成粒度约束（提交 `27f9b10`）

用户问「每周主题到第 9 个就成更多动态，是不是没主题了」。**不是**：`report-period.md` 原文
写死「themes 为 4–8 个」，模型稳定给满 8 个；第 9 块是代码兜底——`compose.ts:265-276`
把未被任何主题引用的条目按 20 条一批切成「更多动态 N」。

**关键实测（W43，同一批 120 条，四组对照，成本共 ¥0.15）**：

| 提示词 | 主题数 | 覆盖 | 遗漏 |
|---|---|---|---|
| 4–8 个（原） | 9 | 78/120 | **42（35%）** |
| 不设上限、每主题 3–20 条 | 20 | 109/120 | 11 |
| 8–12 个 + 全覆盖 | 14 | 112/120 | 8 |
| **每主题至少 10 条** | **10** | **115/120** | **5** |

结论：**主题数不是被上限卡住的，是被「覆盖完整性」和「每组粒度」共同决定的**。
8 个主题之所以成立，正因为只挑了 63% 的条目。写字数上限（8–12）模型根本不听（给了 14），
只有「每主题至少 N 条」这种粒度约束能压住。小周（22/45 条）会自动收敛到 8 个主题、覆盖 96–100%。

**落地**：`report-period.md` 改用 `{{minPerTheme}}`（周报 10、月报 20），加「每条必须归入
某个主题、不允许只挑代表」；`PeriodSchema` 的 `slice(0,10)` → 20（**原上限会静默丢整组主题**
→ 那些条目全掉进兜底块，是隐藏 bug）；`maxTokens` 4000 → 6000。重跑 W43 后 11 个主题覆盖
112/120（93%）、兜底从 56 条降到 8 条。

**待定**：其余 12 期历史周报仍是旧结构（重跑约 ¥0.4）。
