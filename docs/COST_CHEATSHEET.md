# Yi-Hot 成本速查卡（报价用）

> 快照 **2026-10-31**。所有单价来自线上 `service_prices` 表与 `budgets` 表，所有「实测」来自
> `receipt_attempts` 的 7 / 30 天窗口。改模型、改熔断、改信源规模后必须重算，见文末命令。
> 详细推导在 `docs/FINANCIAL_PLAN.md`；本卡只装「能背下来、能当场报出去」的数字。

---

## 一、API 单价（唯一权威，别记成模型名去反查）

`service_prices` 表，CNY，**每百万 token**：

| 服务 | 时段 | 未命中输入 | 缓存命中 | 输出 | 请求费 |
| :--- | :--- | ---: | ---: | ---: | ---: |
| `llm`（deepseek-flash） | **空闲**（其余全部时间，含周末） | ¥1 | **¥0.02** | ¥4 | — |
| `llm`（deepseek-flash） | **高峰**（北京工作日 09–12、14–18） | ¥2 | ¥0.04 | ¥8 | — |
| `deepseek-tools`（网页搜索） | 不分时段 | — | — | — | **¥0.005/次** |

**三个必背的比例**：

- **缓存命中价是未命中的 1/50**（¥0.02 vs ¥1）。缓存是最大的折扣，不是"优化项"。
- **输出价是输入价的 4 倍**（¥4 vs ¥1）。
- **高峰是空闲的 2 倍**，但高峰只占当前花费的约 **2.5%**（避让已生效，这块没有可砍空间了）。

## 二、单次与单篇（实测）

| 指标 | 数值 | 口径 |
| :--- | ---: | :--- |
| 单次模型调用 | **¥0.0013** | 49,904 次 / ¥66.02 |
| 单次网页搜索 | **¥0.005** | 2,407 次 / ¥12.04 |
| 单篇新稿（全流程） | **¥0.0032** | 7,484 篇样本 |
| 单篇回填稿 | ¥0.0040 | 重试多，略高 |

**为什么入池比入库贵 8 倍**：入库 13,602 篇只有 22.6% 过门槛，其余在预筛/评分被拦。
拦截本身省钱（不写摘要、不结构化），但分母仍算全流程。

## 三、钱到底花在哪（近 7 天，27,171 次调用）

| 段 | token | 金额 | 占比 |
| :--- | ---: | ---: | ---: |
| 未命中输入 | 24.56 M | ¥24.56 | **74.8%** |
| 输出 | 1.63 M | ¥6.53 | **19.9%** |
| 命中输入 | 47.57 M | ¥0.95 | 2.9% |
| 高峰溢价 | — | ≈ ¥0.8 | 2.5% |

缓存命中率 **65.9%**（47.57 / 72.1 M）。平均一次调用：输入 2,656 token、输出 60 token。

**结论**：钱只在两个地方 —— **未命中输入（3/4）** 与 **输出（1/5）**。
但正文长度已经砍到边界（首 400 + 尾 400，再砍就误判），所以**真正还能动的是命中率与输出格式**，
不是"把正文再缩短"。

## 四、一条信源多少钱

| 项 | 搜索型 `search` | 官网列表 `web_list` | RSS 大源 |
| :--- | ---: | ---: | ---: |
| **一次性（首采回填）** | ¥0.20 | ¥0.20 | ¥0.20 |
| **每月** | **¥1.50** | **¥0.22** | ¥1.85 |
| 每年 | ¥18 | ¥2.6 | ¥22 |

- 一次性：实测 ¥0.09/条（10-23、10-24 回填 ¥17.98 ÷ 200 条），上界 ¥0.19，**报批一律按 ¥0.20**。
- 月度按「当前投产强度」算（¥1.50 拆开 = 模型 ¥1.04 + 搜索 ¥0.46）；按 30 天均值只有 ¥0.25，
  两者差在「扩源前的低量期」。**编预算取高值。**
- 搜索型是列表型的 **7 倍**，不是因为源贵，是它每月多产 4 倍稿 + 每篇多付检索费。

## 五、加 200 条源，最多多少钱

| 口径 | 一次性 | 每月 | 每年 |
| :--- | ---: | ---: | ---: |
| 全列表型 | ¥40 | **+¥44** | +¥528 |
| 按现状结构（搜索≈42% / 列表≈51%） | ¥40 | **+¥150** | +¥1,800 |
| **全搜索型（最坏）** | ¥40 | **+¥300** | +¥3,600 |

**最坏合计：¥119 + ¥300 = ¥419/月**，仍在熔断线 **¥431/月** 之内 —— 即使 200 条全上最贵的搜索源，
技术上也不会突破封顶。这是对财务申报最有力的一句话。

## 八、对外报价（一句话版）

> **月度 ¥195（变动 ¥150 + 固定 ¥45）、年度 ¥2,340、一次性 ¥50；技术上封顶 ¥440/月。**
> 实际运行成本 ¥127/月，报 ¥195 是留 50% 余量给「选题突发 + 加源」，不是虚报。

配套两句论据：

- **单篇入池 ¥0.027**，人工整理同类资讯市场价 ¥20–80/条，差 3 个数量级。
- **加源本身几乎不花钱**（一条 ¥0.2 一次性、¥1.5/月），贵的是"源带来的稿量"，
  所以预算单位是「篇」不是「源」——这句最容易被理解错，必须主动说。

## 九、怎么"砍价"（按能省的钱排序）

| # | 杠杆 | 能省 | 现状 | 还能动吗 |
| ---: | :--- | ---: | :--- | :--- |
| 1 | **固定成本**：腾讯云续费 ¥510/年 → 促销价 ¥99/年 | **¥411/年 ≈ ¥34/月，最大的一笔** | 首年促销 | 双 11 / 新客券 / 迁机，**唯一真能"谈"的** |
| 2 | **提缓存命中率**：静态 system prompt 放最前、动态内容后置 | 命中率每 **+10 个百分点 ≈ ¥30/月**（7 天 72.1M 输入，10pp = 7.21M token 从 ¥1 掉到 ¥0.02） | 65.9% | 可动，但要改 prompt 顺序，需回归测试 |
| 3 | **压输出长度**：只让模型输出需要的字段 | 输出每减 30% ≈ **¥8/月** | 平均已只 60 token | 边际小 |
| 4 | **削正文截断**：首 400 + 尾 400 字 | 已落地，**但它不是省钱手段** | 800 字是判定质量的最优（字数相同，改判 0 vs 3 篇） | **不要再往下砍**，砍了就误判 |
| 5 | **堆到空闲时段**：半价 | 理论最多 50% | 高峰仅占 2.5% | **已无可砍**（`ANALYZE_OFFPEAK_ONLY` + 8 篇/小时） |
| 6 | 换第三方聚合网关（freellm / omniapi 等） | 名义单价可能更低 | 未验证 | 风险：模型名不在价表 → 成本记 NULL（记账失真）、可用性、数据外发；**只在 translate/monitor 试跑** |

**不能砍的两项**：网页搜索 ¥0.005/次（官方定价，无阶梯）、带宽（用量不到套餐零头）。

**DeepSeek 官方没有商务谈判通道**——按量计费，拿得到的"折扣"只有两个：缓存命中价（1/50）与空闲半价。
所以别去找销售谈，把力气放在第 1、5 条。

## 十、复算（资助方可自己跑，不需要账号）

```bash
# 总账：按天拆 新稿 / 回填 / 搜索 + 单篇均价
sudo docker exec aihot-api-1 node --experimental-strip-types scripts/cost-report.ts 30
# 熔断值
sudo docker exec aihot-db-1 psql -U aihot -d aihot -c "select * from budgets order by 1;"
# 单价表
sudo docker exec aihot-db-1 psql -U aihot -d aihot -c "select * from service_prices order by 1,2;"
```

**口径三条**（被问到时照说）：时间戳是 UTC（与北京差 8 小时）；金额以 `receipt_attempts` 为准（含重试）；
只统计 CNY，USD 单列不跨币种相加。

## 附：最容易记错的五件事

1. 「¥43/月」是 30 天均值，含扩源前的低量期，**不能拿来报价**；报价用 ¥119/月这一档。
2. 「缓存命中 ¥0.02」不是打折，是官方价，命中率 65.9% 是三段 prompt 稳定的结果。
3. 「加 200 条源」不等于「成本涨 200 倍」——按结构算是 +¥150/月，最坏 +¥300/月。
4. 「砍零产出源能省钱」是**错的**：18 条零入池源合计 ¥1.23/月。
5. 「高峰翻倍」听起来可怕，实际只占 2.5%——避让早就做了。
