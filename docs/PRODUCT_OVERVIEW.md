## 一、为什么做

公益信息分布在政府公告、社会组织、行业媒体、微信公众号与邮件简报里。逐个追踪耗时，订阅聚合又容易被重复信息淹没。Yi-Hot 尝试把**来源发现 → 内容去重 → 公益相关性判断 → 事件归并 → 主题与周期性总报**串成同一条可回溯的工作流，读者可以直接跳到原始发布方核验。

面向公益从业者、研究者及关注公共议题的读者。这是**独立维护的公益信息工具**，不是 AIHOT 或救助儿童会官方发行版；机构标识与文章版权仍归原权利人。

## 二、能力地图（区分功能、运营状态与资料来源）

| 阅读者看到的结果 | 背后发生什么 | 重要边界 |
| --- | --- | --- |
| 最新动态、精选筛选、未读筛选 | RSS、网页、邮件简报、JSON、按主题的搜索线索等进入统一数据模型，按来源级别进行抓取和质量检查 | 公众号与微博通道状态会改变，不能用“代码支持”代替“目前在抓”；seed 不是线上信源总量 |
| 同一事件的热点与时间线 | 归并跨来源报道，按独立来源数与时间计算关注度 | 搜索线索不自动等于经独立信源核实 |
| 中文标题、摘要和主题标签 | AI 预筛、评分、结构抽取、写作，保留来源和人工诊断条件 | 内容存在误判风险，不能替代原文；费用与调用次数应按实际回执 |
| 主题与机构阅读 | 公益领域词表、别名、主题映射及历史标签回填 | 内容形式和公益主题是不同分类轴 |
| 周报、月报、邮件订阅 | 按自然周期发布、双重确认、定期投递、可退订 | 旧日报路由留存，不代表仍每日生成新日报 |
| 监管记录 | 单独采集、存储民政部有关行政处罚、异常与失信公告 | 必须区分处罚、列入、移出、送达；历史记录不能直接断言当前状态 |
| 公众号历史内容分析 | 历史公开内容的统计和主题呈现 | 静态专题，不是实时监管或实时媒体报告；不要公开原始全文语料 |
| RSS / Agent / API / MCP | 与网页共用公开读取层，给外部工具访问已公开的信息 | 不能因为开放读取就公开后台配置、邮箱、密钥或用户数据 |

## 三、儿童公益主题：12 个具体方向 + 1 个兜底分类

源码 [`industry/save-the-children.ts`](../industry/save-the-children.ts) 中的 `SAVE_THE_CHILDREN_TOPICS` 是**当前唯一事实源**，2026-10-30 核对如下：

**儿童教育、营养健康、性别平等、儿童保护、网络保护、青年发展、亲子养育、残障融合、应急救援、环境保护、募集筹款、政策倡导；其他领域为兜底标签。**

- “其他领域”不应与已命中的具体使命主题并列，以免扩大兜底。
- “政策 / 研究 / 项目 / 观点”等**内容形式**不是上述公益主题；一篇内容可以同时有形式与主题。
- 主题适用于前台导航、语料标注和历史文章回填，词表与前台应保持一致；详情见 [主题轴迁移](topic-axis-migration.md)。
- 项目维护者曾分析救助儿童会微信公众号 2014–2026 的历史公开文章，仓库当期 README 记载 **1,992 篇**。这个数字是**当期专题研究口径**，不能当作今日持续更新的抓取数。阅读入口：[公众号内容分析](https://49.233.72.222/about/dashboard)。

## 四、产品体验与数据边界

手机端的阅读入口以「总报 / 动态 / 热点 / 主题 / 更多」组织，电脑端使用侧边导航。其他不显眼的功能（监管、Agent、订阅、管理员后台）见 [完整站点地图](SITE_MAP.md)。

**三条基本约束：**

1. **可追溯**：保留真实原文地址，发布时间和抓取时间严格区分；默认只展示摘要和链接，全文权限取决于来源与许可。
2. **可治理**：候选信源进入正式采集前应验证；`industry/sources.json` 为 seed，生产实际启用源以数据库为准。
3. **可恢复**：读者打开网页不应重复调用付费模型；后台处理、预算、失败回执、队列归档要能审计和恢复。GitHub commit 不等于腾讯云生产版本。
