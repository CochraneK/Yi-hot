## 竞品调研：zhangheqing11/PsyHOT 如何接入小红书（读源码结论）
- 仓库：`https://github.com/zhangheqing11/PsyHOT`（心理学/精神医学版 AIHOT 改造，MIT，TypeScript，94 正文信源）。**同源框架**，`receipts.ts`/`budgets` 与我们 yihot 几乎同版。
- **核心结论：没有自建 xhs 爬虫，也不处理签名/风控；全部走付费第三方 EveryInfra 的「公开内容 API」**。xhs 只是 `json_list` 的一个 `adapter: "everyinfra_xhs"` 分支。
- 15 条 xhs 信源（`industry/sources.json`）：10 条 `everyinfraAction: "search"`（keyword + `date_range: last_7_days` + `sort: newest`）+ 5 条 `everyinfraAction: "user_posts"`（`user_id` 24 位 hex + limit 20）。全部 kind=json_list / tier=T2 / interval_minutes=1440。
- 代码路径：
  - `packages/backend/src/providers/everyinfra.ts`（163 行）：`POST /api/v1/social` body `{platform, action, params}`；xhs 三 action = `search` / `user_posts` / `note`；全部经 `paidRequest` 落 receipt。
  - `packages/backend/src/sources/json-list.ts`：6 处 `c.adapter === "everyinfra_xhs"` 默认字段（results / title / text / url / id / author_name / posted_at）；无 url 的笔记丢弃；`summaryIsBody` 让列表摘要直接当正文。
  - `packages/backend/src/sources/collect.ts:148-171`：`everyinfraDetail` 时先 `storedTitles` 查库，**已入库 URL 不再付详情费**；`BudgetExceededError` 时 `break` 而非 throw（保住已付费列表，用摘要入库）。
  - 互动数 `like_count/collect_count/comment_count/share_count` 只收 number 类型（"5" 字符串丢弃），存 `articles.raw`。

### 故障 2：公众号内容实际停更 7 天（未修，需用户扫码）
- `feeds.sync_time`（WeRSS 自己的库，路径容器内 `/app/data/we_mp_rss.db`）：公益时报 `2026-10-13 08:52:56`、AmCham `2026-10-13 09:24:53`，**此后 7 天零次成功同步**；爱德传一 `sync_time=0` 从未同步。
- feed 仍在返回 200 + 30 条，但最新条目分别是 `2026-10-12` / `2026-10-08`。**接口健康 ≠ 内容新鲜** —— YiHot 侧 `health=ok`、`fail_count=0`，完全没报警。
- 微信读书兼容层（`yihot-weread.timer`，每 2 小时）：`WereadMPAPIError code -2012`，首次 `2026-10-13 10:53`，**86 次运行 84 次失败**；journal 里 `"added"` 只有 0，**该层从未贡献过一篇文章**。
- WeRSS 容器 `Up 7 days`，日志无 200013 / 登录错误，但也没有任何同步活动 → 刷新路径实际只有微信读书这一条，它挂了就全停。
- 结论：**不是"多久失效一次"，而是这套公众号采集自 10-13 部署起就没稳定跑起来过**。恢复需重新扫码（微信读书页 + 公众平台），走 SSH 隧道 `ssh -N -L 18001:127.0.0.1:18001 ubuntu@49.233.72.222`。
- **产品缺口**：现有 health 只看「fetch 成功/失败」，需补「内容新鲜度」信号（max(published_at) 距今天数），否则 feed 可读但停更的情况永远静默。

## 公众号扫码有效期实测（回答"多久扫一次"，10-20）
- **WeRSS 根本没有定时刷新**：`docker logs` 第 164 行打印「没有任务」，`message_tasks` / `message_tasks_logs` / `config_management` 三表均 **0 行**。`jobs/mps.py:start_job()` 靠 `message_tasks.cron_exp` 注册 APScheduler 任务，表空就直接 return。→ 10-13 之后那 43/80 篇是首次扫描存量，`feeds.sync_time` 冻结在 10-13 08:52/09:24 与此吻合。
- **实测刷新一次**（`GET /api/v1/wx/mps/update/MP_WXS_2395372392?start_page=0&end_page=1`，Bearer token 由 `/api/v1/wx/auth/login` 取，凭据从 `/opt/werss/.env` 经 stdin 传入）：返回 `time_span=664641`（通过 60s 防抖）但 `total:0`，线程内抛 `core.wx.model.weread_mp.WereadMPAPIError: -2012 登录超时`（日志同时打印「采集模式:weread_mp」）。60s 内 sync_time/articles 无变化。→ 确认凭据死，不是"没新文章"。
- **两条通道 TTL 完全不同**：
  - `wx.lic` 的 `token_data.expiry.expiry_time = 2026-10-16 22:07:37`，`remaining_seconds=345595` → 登录（10-12 22:07，key.lic 创建时间）后**整 4 天**硬过期；10-13 08:45 重新扫码**未延长**该时间。→ web 模式约每 3–4 天扫一次。
  - `weread_data.cookie` 仅 79 字符（`wr_skey=…` + `vid`），无 ticket/无过期字段；实测 10-13 08:52 可用 → 10-13 10:53 即 -2012（约 2h，单样本）。
- **MP_WXS_* 强制走 weread_mp**（`jobs/mps.py:72`）：`mp.id.startswith("MP_WXS_")` 且存在 weread cookie 时自动切 weread 采集器。→ **只扫公众平台二维码不会恢复这三个号**，必须刷微信读书 Cookie，或改 feed id/清空 weread cookie 才能回落到 web 模式。
- **无自动保活**：`core/weread_cookie_refresh.py` 的 `request_host_refresh()` 依赖宿主机 `host_weread_refresh_agent.py`（默认 `http://host.docker.internal:9876/refresh`），该代理是给 macOS 本机 Chrome 写的（钥匙串解密 profile）；腾讯云 `/opt/werss/` 下只有 `collect-weread.py` 与 `weread-list-compat.py`，**代理不存在** → `triggered=False` 静默跳过，永不自动续期。

## 21:45 公众号批量纳号：上限、筛选、检索三条实测结论
