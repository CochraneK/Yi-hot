# 共创与共养

> 一句话：把「同一套引擎」的重复劳动和运行费用，变成一件可以共同承担的事。
>
> **状态：提案。未与上游沟通，也没开始任何收款。** 下面凡是没验证过的，第六节单独列出来。

## 一、三个问题，三套解法

| 问题 | 现在是什么样 | 该由谁解 | 见 |
| :--- | :--- | :--- | :--- |
| **重复** | 上游 2,125 个 fork、8.9k star，公开的自建站至少 16 个，其中 5 个是「独立实现」——同一个领域两个人从零写一遍采集器 | 缺的不是热情，是**登记**与**可复用零件** | 二 |
| **钱** | 单站成本在每月一两百元量级，由作者一个人掏；想认真做的人先被这份固定支出劝退 | 小额、可退、透明的**订阅**，不是募捐 | 三 |
| **孤岛** | 每站一个域名、一个领域，读者要开十几个标签页 | **联邦索引**，不是把内容混进一个池子 | 四 |

三件事有先后：**登记 → 零件 → 钱 → 索引**。顺序颠倒就会变成「先发动大家捐款，再发现没人知道钱该给谁」。

## 二、去重：先登记，再动手

### 2.1 领域注册表

一张表，放上游 README 或一条置顶 Discussion，字段只要六个：

```
领域 | 站点 | 仓库 | 许可 | 联系方式 | 状态（在建 / 在线 / 停更）
```

规则三条：

- **注册不等于所有权。** 同一个领域允许两家并存——编辑立场不同是合法的，心理学里学界和业界两套标准都能活。但你要能看见对方。
- **先查表再动手。** 表上一片空白的领域，随便做；表上已经有两家的，先问一句「我能不能补你缺的那块」。
- **停更要标出来。** 一个停更两年的站还挂在表上，等于把后来的人挡在门外。

成本几乎为零，但它解决的是最贵的问题：**一个人花三个月重写的东西，另一个人三个月前已经写完了。**

### 2.2 真正省钱的是零件，不是劝退

重复劳动的大头不在「决定做哪个领域」，而在每个站都要重写一遍的东西。按本站的经验，最常被各站各写一遍的是：

| 零件 | 为什么每个站都在重写 |
| :--- | :--- |
| 列表页适配器（`fromHtml` 选择器） | 「这个政府站没有 RSS」是所有人的共同问题，解法是同一套选择器 JSON |
| 日期解析 | 中文「2天前」「2026年10月21日 17:45」「只有月日没有年」，每家踩一遍 |
| TLS 握手兼容 | 部分政府站的 TLS 栈只认 P-256，Node 默认协商会失败（已提给上游） |
| 公众号通道 | 免费方案要长期维护扫码会话；付费方案各站各买各的额度 |
| 计价与成本口径 | 命中价、高峰价、按 service+model 匹配，写错了就长期高估 |

**提议：适配器以数据回贡，不以代码回贡。** 每解决一个没有 RSS 的站点，贡献的应该是一段选择器 JSON + 一条验证记录，而不是一个 fork。选择器 JSON 能直接进 `sources.json`，代码不能。

## 三、钱：一元订阅怎么设计才站得住

### 3.1 先算量级，再谈情怀

| 口径 | 数字 | 说明 |
| :--- | :--- | :--- |
| 单站月度成本（本站实测） | **约 ¥110–130** | 模型 ¥93–123 + 服务器 ¥8.25，稳态 |
| 覆盖这些成本需要多少人 | **110–130 人** | 每人每月 ¥1 |
| 60 万月活 × 0.05% | 300 人 → ¥300 | 转化率取低 |
| 60 万月活 × 0.1% | 600 人 → ¥600 | 常见订阅转化区间 |
| 60 万月活 × 0.5% | 3,000 人 → ¥3,000 | 只有把付费入口放在读者必经处才可能 |

结论：**「一人一块能养活」在数量级上成立**，但有两个前提常被忽略——

1. **60 万是内容平台的读者，不是网站访客。** 公众号打开率通常个位数百分比，能一路点到站内、再点进付费页的比例更低。乐观算法要打两到三次折。
2. **一元钱的收款成本占比极高。** ¥1 的支付通道费率、提现门槛、退款处理，会把小额订阅的实际到账压掉一截。要么设「¥12/年」降低频次，要么接受这部分损耗。

### 3.2 定性：订阅，不是捐赠

这是整件事最要紧的一条。**把它写成「每月一元订阅，换无广告、无追踪、报告先收到」，不要写成「捐助公益」。**

- 公开募捐在中国受《慈善法》约束，需要资格认定；个人主体做公开募捐是明确的风险区。
- 订阅是**有对价的交易**，捐赠是**无偿给付**——定性错了，退款、税务、平台规则全都会跟着错。
- 真要捐给行业，走有资质的机构、能开票、能公示，而不是从个人账户转出去。

（具体条款请法务确认，本文只给方向。）

### 3.3 钱进来之后，先定分配顺序

三档，按顺序，不能跳：

1. **当月账单**——模型 API、服务器、对象存储。先保命，这一档没付清之前不谈其他。
2. **三个月备用金**——攒够就停在这一档。防止某月收入归零就直接停站。
3. **剩余部分**——维护者劳务，或捐给有资质的行业机构。给维护者的那一份要**事先讲清比例或上限**，事后分配必然起争议。

### 3.4 透明比口号有用

每月一行账，放站点页脚，公开可查：

```
2026-11 ｜ 收入 ¥612（612 人）｜ 模型 ¥118 ｜ 服务器 ¥9 ｜ 余额 ¥485 ｜ 本月未分配
```

再加三条硬规矩：

- **钱与作者个人账户分离**，哪怕只是一个专门的子账户；
- **达到当年预算上限就停收**（比如已攒够 12 个月账单，就把入口关掉，写「已满」）。这一条是把「共养」和「生意」分开的唯一标志；
- **随时可退**，不问理由。一个人的一元钱不值得他为此写一封邮件解释。

## 四、汇总：联邦索引，不是混池

每个站都已经具备做联邦的技术条件：统一的 `/feed.xml`、公开 API、`llms.txt`、`sitemap.xml`。实测 8 个站的 feed 全部可用。

但「汇总」有两种做法，差别很大：

| | A. 联邦索引 | B. 混池 |
| :--- | :--- | :--- |
| 存什么 | 标题 + 链接 + 来源站 + 时间 | 全文进自己库，参与自己的评分 |
| 读者去向 | 点进去到原站 | 留在本站 |
| 领域问题 | 不存在（各看各的） | 机器人、影视、营销、心理学混进公益池 |
| 成本 | 一次抓取，零模型调用 | 每篇都要预筛 + 评分 |
| 版权 | 只引用标题，安全 | 转载全文有风险 |
| SEO | 互相导流 | 重复内容互相稀释 |

**本站已经验证过 B 不可行**：把衍生站 RSS 接成本站信源，只会稀释入池率、增加成本、让首页出现无关内容。所以汇总要做成 A：

- 元站点（或站内一页）只读各站 feed，缓存一小时，失败静默降级；
- 每条明确标注来源站与许可，点击直达原站；
- 不镜像正文、不缓存图片、不参与自己的选稿评分。

落点有两个选择：**站内加一页**（2C2G 的机器要多一份抓取和缓存，收益是「站内能看到别人在写什么」），或**上游做一个聚合仓**（一次抓取，所有站共用）。后者更省，但需要上游点头。

## 五、谁先动，动什么

**三十天内、不用任何人同意就能做的：**

1. 在本仓库写清「我们做过什么、哪些不要再做一遍」——本文第二节的零件清单就是雏形；
2. 给 [想法台账](IDEAS.md) 加一条「领取」标记：谁能做、卡在哪；
3. 把月度成本账做成可公开的一行数字（现在已经有 `cost-report`，差一个对外页面）。

**需要上游点头的两件：**

1. 领域注册表落在哪儿（上游 README / 置顶 Discussion / 独立仓）；
2. 联邦索引由谁抓、署谁的名、失败算谁的。

**现在不建议做的：**

- 自建支付、积分、代币、等级体系——一元钱撑不起一套经济系统；
- 在文案里写「捐助」「公益募捐」；
- 先收钱再想分配比例。
