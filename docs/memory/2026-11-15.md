### 一个坑：裸 fetch 测不出重试

先用 `node -e 'fetch(...)'` 测 `mzt.hunan.gov.cn` → `ERR_SSL_BAD_ECPOINT`，以为上游那条修复没吸收。
**错**——裸 fetch 绕过了 `guardedFetch` 的重试。改用真实的 `guardedFetch` 后：
**200 / 305ms**。容器内代码本来就有 `pinnedCurve`（5 处）。
教训：**测出网行为必须走项目自己的封装**，否则得到的是假阴性。

附带实测：`https.get` 用 `ecdhCurve:'auto'` 报 EPROTO，而 `X25519`/`prime256v1`/`X25519:prime256v1` 任一显式值都 200。
所以「auto 一次发多个 key_share 才是根因」，不是「服务器拒绝 X25519」——比上游 commit message 的说法更准。
但既然现有重试够用，不改。
