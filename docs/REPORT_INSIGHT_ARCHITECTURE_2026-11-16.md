# YiHot · 从摘要到证据分级洞察（2026-11-16）

本文件是日报、周报、月报、年报的**设计与验收唯一主线**。按真实仓库核对，当前可发布的 `ReportKind` 仅有 `daily / weekly / monthly`；**年报尚未实现**，不得把已有公众号长周期 Dashboard 冒称公益行业年报。本阶段仅把**周报/月报**的证据洞察做成代码，日报与年报按后述阶段推进。

## 诊断：为什么现在只有 summary

- `packages/backend/src/reports/compose.ts`：日报拿本期入选稿件写一次 `report-daily-lead`（头条和重点编号）。周报、月报对已收录合格条目去重，只取最高分的前 120 / 300 条输入同一个 `report-period.md`；原提示词主要要求主题覆盖，返回 `overview/themes/refs`，**没有比较基线、竞争解释、可检验问题与独立的证据引用结构**。
- `ReportPaper.tsx` 版面已经有报头、头条、看点、板块、单条引用、邻域与历史期刊。问题首先是“**分析语义/证据合同**”，不是再换一个更漂亮的模板。
- **报告时间不是自然世界的完整抽样**：来源新增/暂停、媒体转载、搜索迟到稿、撤回、`eligible/selected` 不同门槛都会改变入池数量。不能拿“本站报道变多”推断“全国慈善活动真实变多”，也不能用评分或文章数量当结论置信度。
- **生成周期与模型调用边界**：日报每天 08:00，一期一段导语模型调用；周报周一 06:00，月报每月 1 日 06:30，各有原本一次 period 模型调用。报告支持旧期重编并保留 revision；本阶段不自动重编历史、不新建定时任务或额外收费调用。

## 五层内容，不是五段相似的文案

| 层 | 要回答的问题 | 允许的材料 | 展示和证据标准 |
| --- | --- | --- | --- |
| L0 事实 | 原文到底说了什么？ | 已公开的原文与当前版本 | 原文链接、主体、时间；撤回后标记不可读 |
| L1 变化 | 与之前相比，哪些事实新增、落实、转向或纠正？ | 同一事件的前后事实及明确时间 | 日报优先；不能把“首次被本站看到”当成“首次发生” |
| L2 模式 | 不同事件之间有没有共同方向、矛盾或关联？ | 至少两条不同事件，来自至少两个独立来源 | 周报优先；说清样本范围与其他解释 |
| L3 机制 | 哪些机制**可能**解释这些模式，有什么竞争解释？ | 跨主题/跨期证据、对照、反例 | 月报优先；标“分析假设”，不冒充已证实因果 |
| L4 回顾与前瞻 | 哪个结构性转折经过了检验？哪些预测被证伪？ | 年度纵向数据、此前监测点及后验追踪 | 年报优先；有证据链、观测缺口及失效案例 |

**总原则**：结论层级不由模型自评得分决定，而由引用是否有效、来源是否独立、时间对照是否可比和反例是否回应来决定。输出层级和有无洞察必须是可以为零的，不为每期强凑“十大趋势”。

## M1 · 周报和月报的第一层代码（本轮）

改动入口：

- `industry/prompts/report-period.md`：原有资料归档 `themes` 保留，在**同一次** period JSON 输出中尝试增加最多 3 条 `insights`。每条必须含 `claim/reasoning/alternative/watchFor/refs`，分别对应判断、推理、竞争解释、下期验证指标与原始条目编号；证据不足就 `[]`。
- `packages/backend/src/reports/insights.ts`：编号必须命中本次模型实际看到的材料；至少两条不同事件、两个不同技术信源；重复编号、无效编号、只靠同源转载或无替代解释全部丢弃。周报输出 `pattern`、月报输出 `hypothesis`，模型无权升级为“确证因果”。
- 对比上期的**候选样本**、来源覆盖和主题份额作为提示词的上下文：上期样本过小或来源集合变动大时声明不可比；即便可比也只称“本站入池样本占比”，不能外推外部世界。对比使用已有数据库读取，不新增模型请求。
- `packages/backend/src/publication/reports.ts`：只公开仍存在且可访问的证据；任一引用撤回或失效则**整条洞察隐藏**，防止结论在没有依据时留在页面。旧报告没有 `insights` 时保持原样；原文、主题、摘要和历史 revision 不迁移、不重写。
- `ReportPaper.tsx`：在新闻板块之前新增不超过三条紧凑的“本期洞察”：判断、理由、另一种解释、下期验证、可点击的当前原文依据。不额外创建导航顶栏、不改变日报版面；符合 less-is-more。

**限制必须公开**：模型只看筛出的最高分 120 / 300 条摘要（尽管所有合格条目仍会完整归档），洞察因此是**编辑样本上的解释**，不是全库统计定论。不同 RSS 技术信源不一定代表真正独立的发布主体，M1 的“两信源”只是最低形式闸门，尚需人工核对是否转载同一报道。模型输出新增字段会增加单次上下文/生成 token，**不会增加请求次数，但不能声称完全没有新增成本**。

## M2 · 日报 L1：事件“有什么新变化”

不把每条新文章重新写一次“这很重要”。从同一 `story/fact` 的版本序列中检测并显示 `new / advanced / corrected / contradicted / unresolved`；要有事实日期与先前事实引用，未捕捉到变化时只显示日报头条。最有价值的是“上期仍未回答的问题→本期出现的证据”，不是新增三个固定段落。优先复用日报一次导语调用和已有事实/事件索引；上线前做时间混淆、机构所在地、转载和跨语种误差样本验收。

## M3 · 月报 L3：可比数据与竞争解释

由 M1 的“候选样本对照”升级为**同源配对窗口**：相同来源、相近抓取可用性、固定标签口径、迟到稿/撤回修正、按自然日归一；不能对比的板块明确标“观察不足”。每个机制假设需至少一条潜在反例或替代机制，并标下一期可查证的来源/日期/指标。把“来源覆盖扩大”与“行业变化”正交显示。必要时通过小规模人工复核校准，不为凑分级增加多 Agent 自我评价调用。

## M4 · 年报 L4：独立产品，不是把十二个月拼成一篇

年报需新增 `ReportKind = annual`、`YYYY` 年度索引与归档、数据库 kind 约束核对、跨年导航、年报封面和公开 DTO、邮件订阅选项（另做用户同意）、独立审批/成本预算与新任务调度。**这些本轮未实现**。

年报应使用年度候选事实图、12 月或 52 周的证据节点和同比基线，重点回答：年度重大转折是什么，哪些曾经预测的机会/风险后来被证实或证伪，哪些机构行为或政策发生持久变化，尚存哪些观察盲点。没有可靠全年数据时发布**覆盖范围声明与专题回顾**，而不是假装“2026 全国公益年度全貌”。上线顺序：离线草稿 → 抽样核验 → 人工批准 → 有界公开发布 → 最后才考虑自动定时。

## 最小验收与成本纪律

1. **单元测试**：编号、同源、同事实、缺失反例、重复结论全部拒绝；撤回任一引用后不再公开整条洞察；历史报告兼容；可比性警告覆盖数据极少及来源变化场景。
2. **合成 CI**：typecheck、Web build、既有后端/PG/Docker回归全绿；测试不连真实第三方，不跑付费模型。完成代码后只能称“实现能力”，不能称“生产已生成深度洞察”。
3. **真实抽检**：选至少 30 条洞察候选，逐条核查引用能否支持、是否多源独立、是否事实与假设混淆、反例是否有意义；发现无法确认就降级或拒绝。至少再抽 10 条旧期摘要做盲评，比较“是否真正增加了信息增量”，而不是只看写作评分。
4. **费用验收**：对比旧/新 `report_weekly/monthly` 回执的实际输入/输出 token 和人民币金额；超过设定预算再调整每期 insight 上限，不额外启动第二轮“反思模型”调用。
5. **历史回填和生产部署**：本轮**不自动修改旧报告、无新增迁移、不改变采集/评分/通知/定时开关**。想让旧期出现洞察需要另做受控重编；需明确费用、版本历史和撤回审查。腾讯云是否上线另行核对，不能以 GitHub main 代替部署。

回滚：只撤销 prompt/compose 的额外洞察生成、public DTO 投影和页面 `InsightPage`；旧报告内容与数据库保留，先前生成的 `insights` JSON 仍可被旧版忽略，不需要删除数据或下架。


## M1.5 · 证据叙事优先（2026-11-16 已提交代码，须 CI / 生产验证）

用户指出「日报、周报像很长的 summary」，进一步明确要求每条洞察自然引入**真实新闻发生的事实**，让读者不用先打开大段新闻清单，也能掌握关键材料。本次沿用公开来源、引用核验和不重复付费调用的约束，调整**报告写作与阅读顺序**，不是给原摘要增加更多栏目：

- `industry/prompts/report-period.md`：周/月共用的一次模型生成将叙事优先级给 `insights`，每条提出 0–3 个真正值得联系的跨事件观察。要求新闻编号、有限篇幅的推理、反例、下期可检验指标；不能用「持续发展」冒充发现。保存原 `themes` 为归档，仅写一句索引说明。周报 `overview` 上限建议 75 字、月报 120 字，防止同一层重复叙述。生成模型的实际调用次数没有增加，输入/输出 token 可能变化。
- `industry/prompts/report-daily-lead.md`：日报同一次头条调用只选一件最重要的新事实、1–2 句话讲主体/行动/结果（或限制），另外选择最多三条独立新闻的编号。日报不虚构强行跨期的因果进展。
- `ReportPaper.tsx`：有有效洞察的周/月报告**跳过原本前置的重复摘要头版**，先让读者看到“判断 → 2–3 条有标题、短摘要、站内新闻页和原文链接的现实报道 → 联系与意义 → 可见的替代解释”，观察指标和更多材料折叠。**新闻摘要文本来自目前可公开的原始引用投影，不依赖模型第二次改写**；因此其真实性边界和引用有效性由既有发行层保障。日报保留简短头条与看点；任何报告的全量主题、快讯、邻域仍在页面原地但默认折叠到「完整新闻资料」，并有页内目录，适合读者自主核实。
- **无洞察回退**：没有至少两件独立事件/技术信源支撑时，不生成虚假的趋势；周/月仍回退展示短导语或重点新闻、原始新闻索引可展开；旧的日报/周报/月报不会被自动重编，URL / 期号 / 原文数据合同不变。
- **发表边界**：没有扩大候选源或抓取全文，不自动调整分类门槛，不提前发布新模型结论，不改变 DB、定时、通知、隐私或上线配置。已有候选模型的 `reasoning` 仍只是一种可质疑的解释，两个技术 RSS 入口不自动等于独立新闻发布主体。真实质量验收需要人工比对新闻原文、转载与反例。

验收与回滚：新增 Web SSR 合成期刊测试，检查**洞察比新闻档案更靠前**、至少两条事实标题及其真实格式原文链接、默认闭合的可展开归档、不能在首屏重复旧摘要。另需 typecheck、Web 构建、完整后端与 Docker CI。回滚可恢复两条提示词、`compose.ts` 的短概述限制和 `ReportPaper` 的阅读层，报告储存 JSON 与历史 revisions 无需清理。腾讯云部署与真实付费回执须另外核实。

**后续不变**：日报 L1 同事件跨期变化链、同源可比月报机制检验、独立 `annual` 年报尚未实现，仍由 Issue #68 跟踪。
