# 城市地图、地区筛选与当地新闻（2026-11-16）

## 读者看到的变化

- `/yihot/cities` 默认查询全库公开、可发布的**已审核事件地点**，支持国家、省份/地区、标准地点和数值分页。旧 `?city=chengdu` 链接仍是地名线索；`?city=chengdu&reviewed=1` 仍可查询已审核索引。新链接使用 `?place=<标准地点ID>`，不局限于前端原有60城词典。
- 「地名线索」入口使用 `?reviewed=0`，保留文本搜索，但不进入地图、不触发【当地】。机构所在地、受影响地区或仅被提及的地名不能冒充事件发生地。
- 「加载交互地图」按需启用打包在本站的 Leaflet 1.9.4，直接获取 OpenStreetMap 底图，可拖动、触控缩放、点击标记后在地图下方展示所选地点与本页新闻，并通过可触摸的按钮查询该地点的全库结果；不使用可能被地图标题或手机导航遮挡的浮动弹窗。接近的点按当前缩放级别合并，聚合标签显示“几地”；单点数字是这个地点的不同新闻数量。
- 地图标记与计数按**筛选后的全库**聚合，不随新闻翻页漏掉其他城市；同一新闻有多个地点时，列表只计一次，每个地点各记一次，因此不能把地图各点计数相加当成总新闻数。
- 代表点使用管理员登记的坐标与 city/region/country 精度，**不伪装成事件现场坐标**。附近查询仅使用 city 级代表点，按地球大圆距离计算，能跨越日期变更线；25/50/100/300/1000 公里是预设范围，服务端接受1～1000公里。
- 「我的城市」可从原有城市和已登记的城市级事件地点中选择。「看附近新闻」按所选城市的中心搜索；没有当前位置不触发请求，也不会要求GPS权限。
- 新闻卡片的【当地】统一使用发布层输出的 `eventPlaces`，要求已审核的城市级事件与所选城市匹配。相同国家和地区下规范化城市名可兼容旧城市ID；标题含地名不再足够。

## 地点如何产生

既有 structure 任务提取候选 → 保存原文证据与地点角色 → `/yihot/admin/geo` 人工核对和标准地点登记 → 人工通过 event → 当前版本、当前发布分析、公开状态及精选释放条件均满足 → 地图/地区索引/卡片。

本次没有新模型调用、付费地理编码、自动批准、生产迁移或真实新闻回填。任意地区可通过后台登记有来源的标准地点，不用修改前端词典；但这不等于已导入全国或全球地名库。未经审核的历史新闻不会为了填满地图而被自动补地点。

## API 与数据界限

`GET /api/site/geo` 通过唯一的 publication 读取层查询。参数可组合，组合后取交集：

| 参数 | 含义 |
| --- | --- |
| `place` | 标准地点ID；保留旧接口 |
| `country` | 两位国家/地区代码，不区分输入大小写 |
| `region` | 精确地区名称，必须同时给 country，最长120字符 |
| `lat / lon / radius` | 三个必须同时给；城市代表点、公里。有限数值，经纬度合法，radius在1～1000 |
| `page` | 1～50，每页40条 |

返回原有 `placeId/items/page/pageCount/total/generatedAt`，新增：
- `places`：当前筛选范围的地点与去重新闻数，最多1000个，超出给 `placesTruncated`。
- `catalog`：当前国家/地区的可公开地点选项，最多1000个；`countries` 来自全库公开地点，`regions` 是当前国家/地区的省份列表。可先选国家并筛选，再选省份；`catalogTruncated` 披露选项截断。只登记、尚无公开事件的地点不进入这些选项。
- `totalCapped`：新闻超过2000条时显示 `2000+`，可浏览最近2000条；地图仍聚合当前全范围，请按地区缩小列表。
- 卡片和详情的 `eventPlaces`：只包含地点ID、名称、国家、地区、城市、坐标和精度。**不输出待审候选、证据引文、审核人、内部理由或分析输出。**

撤回、隐藏、精选未释放、原文改版、发布改用新分析、审核重新打开或驳回，均通过当前门槛排除旧地理关联。常规公开接口最多有60秒共享缓存；卡片个人【当地】在浏览器计算，不写入共享HTML。没有基于 Cookie/IP 的服务器个性化缓存。

## IP、地图和本地数据

- IP估计只在点击按钮后连接 `https://ipwho.is/`，对方会收到连接IP；请求8秒超时。只把返回的城市名与国家/地区和现有地点匹配，重名不明确时要求手动选择，不使用返回的精确坐标。没有查到城市仍可正常阅读。
- 本地保存 `yihot:reader-location:v2`：城市ID、名、国家、地区和登记的城市中心。旧 `yihot:reader-city:v1` 可读且对原有ID兼容写入；清除城市同时清除二者。不会存储IP、GPS坐标或浏览位置轨迹，储存被禁用时可继续阅读。
- 地图和IP开关彼此独立。地图不开启就不请求底图，开启后 OSM 会收到连接IP、请求的地图格子和本站域名。格子会间接表明当前地图视野，不能声称对方不知道视野区域。
- 使用标准HTTPS瓦片地址与浏览器缓存，不预取、不批量下载、不建立离线瓦片包。瓦片图片单独设置 `strict-origin-when-cross-origin`，满足 OSM 对Referer的要求，同时避免把筛选参数发给第三方；保留可见署名和问题反馈链接。本站其他页面的 no-referrer 不变。
- 底图属于外部最佳努力服务，大陆连接或服务限流可能失败。失败提示、地点列表、地区筛选和新闻阅读不依赖底图；没有加载底图时同样可操作。

参考：[Leaflet 1.9.4](https://leafletjs.com/reference-1.9.4.html)、[OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)。Leaflet版权和完整BSD声明见第三方声明与 `docs/licenses/Leaflet.txt`。

## 验证与实际限制

本地：typecheck、Web构建、49项Web回归及地理参数校验通过。手机地图曾发现 Leaflet 浮动弹窗操作区被邻近控件遮挡，已改为地图下方的固定流程；国家/地区文案采用稳定字典，不依赖 Node 与浏览器不同的 Intl.DisplayNames 输出，防止 SSR 水合错误。真实构建SSR使用合成HTTP数据，验证默认审核索引、非词典标准地点、服务端筛选参数和旧城市链接。当前沙箱无法启动Chromium，云浏览器不能访问此工作区回环地址；因此不将本地手机视觉/交互验收写成已完成。

CI：`tests/geo-reviewed.test.ts` 用隔离PostgreSQL验证国家/地区、跨日期变更线距离、多地点去重、地图跨页、非城市精度排除、未审与撤回不公开、现有版本/释放门槛。Docker中 `CITY_BROWSER_TEST=1 node --test apps/web/tests/city-browser.test.ts` 必须实际启动Chromium，使用合成HTTP数据和本地拦截的地图/IP响应，检查390px及1440px、地图开关/点击/重建、地区筛选、附近链接、IP按钮和当地标签。不连接真实第三方、不使用真实IP、不花模型费用。

真实新闻100条地点质量、审核覆盖率、腾讯云部署和真实底图可达性仍需目标环境验收。本次实现不能证明AI地理准确率，也不能承诺未审核新闻都已落图。
