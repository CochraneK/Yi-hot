## 失败源重试机制核准（10-08 用户问"失败的 rss 源怎么处理、留重试可能了吗"）

**机制（collect.ts 全读确认，零数据丢失 + 永不永久禁用）**：
- **失败不推进游标**（文件头注释 "A failed fetch never advances the success cursor"）→ 断档期间漏的条目在下次成功时从同一游标补抓，零丢失。
- 失败处理：`fail_count+1`、`last_error=消息(≤1000字)`、`health='degraded'`（连续≥5 → 'failing'）、**`next_fetch_at=now+LEAST(interval*(fail_count+2), 360) 分钟`** —— 240/360min 间隔源第 1 次失败即触顶 **360 分钟（6 小时）**，之后永久每 6h 重试，**永不自动禁用源**。
- `fetch_runs.status='failed'` + error 消息存档（可查历史）。
- 成功：`fail_count=0, last_error=NULL, health='ok'`，游标推进，恢复正常 interval。
- 特例 `BudgetExceededError`（LLM 预算超限）→ 15 分钟快速重试、fail_count **不**累加（非源故障）。
- 调度器每分钟轮询 due 源（`next_fetch_at IS NULL OR <= now`），入队后立刻 +10min 防重复；`COLLECT_SKIP_JINA` 可跳过 r.jina.ai 源。

**DB 实况（10-08 11:38 复核）**：14 源全 `health=ok / fail_count=0 / last_error 空`；历史 failed runs 仅 3 条**全部自愈**：rss-oxfam 10-06 14:29Z "fetch failed"、rss-givedirectly 10-01 09:02Z "timeout"、rss-oxfam 09-30 01:52Z "HTTP 404"。→ 重试可能性完全保留，无需手动干预。唯一盲区：`FEISHU_INTERNAL_ENABLED=off` 长期失败不推送（watchdog 只刷日志）。
