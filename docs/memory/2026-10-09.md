## 新坑（sshexec 传输层）

**sshexec 命令不能含 `||`**：含 `||` 拼接的长参数经本机→远端传输被破坏（`${Q}` 引号变 `/`，echo 可复现）→ 远端 bash/psql 报语法错。**对策**：SQL 用 `VALUES (字面量)` 形式，避开 `||` 字符串拼接；SELECT+IN 列表（无 ||）实测安全。

**关键机制（必记，回答一切「为什么看不到 X」）**：`/all`「全部动态」列表 SQL 强制 `listedCondition(now) AND p.eligible`，按 `p.timeline_at DESC` 排序（**不是 sort_at**）。
- `listedCondition(now)` = `p.visibility='public' AND (NOT p.selected OR p.visible_after <= now)`（`publication/items.ts:80`）——非精选立即显示；精选要等 `visible_after`。
- `p.eligible` = `isPoolEligible({participation_mode, relevance, title, summary})`（`publication/rules.ts:19`）：**必须 `participation_mode='editorial'` + `relevance='pass'` + 有标题 + 有摘要**，缺一即 false。
- 推论：**relevance≠`pass`（被 prefilter 判 BLOCK/UNKNOWN）的内容 `eligible=false`，压根不进列表**；「列表最新一天」由**第一个 eligible 条目**决定，而非采集时间。

**10-09 实况**：采到 5 条（教育部 1 + 最高法 3 + 中国儿基会 1），**全部 relevance≠pass**（4 条 block、1 条 unknown）→ 全部 `eligible=false` → 列表不显示，最新可见 = **10-08**（乐亭县"信访+妇联" 19:31，pass）。线上 `/all` 实测顶部=「10月8日」、右上「今日 0 条」，与 DB 完全一致。
